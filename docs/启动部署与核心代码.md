# 花店会员管理系统 · 启动、新电脑部署与核心代码

本文说明三件事：本机如何启动、换一台电脑如何重新跑起来、系统各块核心代码分别在哪里、干什么。

系统是本科毕业设计演示用的单体 Django 项目。不接真实支付，不需要 Vue / React / Redis / Docker。

- 前台（会员）：http://127.0.0.1:8000/
- 后台（管理员 / 店员）：http://127.0.0.1:8000/admin/
- 经营看板（管理员 / 店员）：http://127.0.0.1:8000/dashboard/

---

## 一、本机已经装好时，怎么启动

在项目根目录（有 `manage.py` 的文件夹）打开 PowerShell：

```powershell
cd "C:\Users\你的用户名\Desktop\Flower Shop Membership Management System"
.\.venv\Scripts\Activate.ps1
python manage.py runserver
```

浏览器打开 http://127.0.0.1:8000/ 即可。停止服务：在运行窗口按 `Ctrl + C`。

如果提示找不到 `python` 或没有 `.venv`，说明环境还没装好，按下一节从零部署。

### 演示账号

| 角色 | 用户名 | 密码 | 入口 |
| --- | --- | --- | --- |
| 管理员 | admin | admin123456 | `/admin/`、`/dashboard/` |
| 店员 | staff | staff123456 | `/admin/`（无用户管理、无直接退款、无充值；可审核取消）、`/dashboard/` |
| 会员 | demo_member | member123456 | 前台购物、会员中心 |
| 其他会员 | member_lin / member_chen / member_zhou / member_wu | member123456 | 同上 |

会员也可自行在 `/accounts/register/` 注册。储值入金有两条路：会员中心「自助充值」（模拟网关），或管理员在后台会员详情填写「储值充值金额」。店员不能充值。

### 常用命令

```powershell
python manage.py migrate              # 同步数据库结构
python manage.py seed_demo            # 导入/补齐演示数据（商品图、会员、券）
python manage.py seed_demo --force    # 删除演示订单后重新生成
python manage.py expire_coupons       # 扫描过期优惠券
python manage.py expire_pending_orders  # 扫描超时未支付订单（进入首页/花市/订单页/看板也会自动扫）
python -m pytest                      # 跑测试（用 SQLite，不动 MySQL）
```

## 二、在新的一台电脑上部署运行

整份项目拷过去就能跑。需要先装 **Python 3.12 或 3.13**、**MySQL 8.0**。下面按 Windows 写；Mac / Linux 只是激活虚拟环境的命令不同。

### 1. 拷贝哪些文件

把整个项目文件夹拷到新电脑，例如桌面的 `Flower Shop Membership Management System`。

必须带上：

- `apps/`、`config/`、`templates/`、`static/`、`media/`、`docs/`、`tests/`
- `manage.py`、`requirements.txt`、`.env.example`、`pytest.ini`
- `media/products/` 里的商品图片（首页花市要靠这些图）

不要依赖旧电脑的 `.venv`（虚拟环境不能跨机器直接用）。  
`.env` 里有本机数据库密码，建议在新电脑重新从 `.env.example` 复制后再填写。

### 2. 安装 Python

1. 安装 Python 3.12 或 3.13，勾选 **Add python.exe to PATH**。
2. 新开一个 PowerShell，确认版本：

```powershell
py -3.13 --version
```

没有 `py` 启动器时，用 `python --version`。本文后面若写 `py -3.13`，按你本机实际命令替换即可。

### 3. 安装并启动 MySQL 8.0

1. 安装 MySQL 8.0，记住 `root` 密码。
2. 确认服务已启动（Windows 服务名一般是 `MySQL80`）。
3. 用命令行或 MySQL Workbench 执行：

```sql
CREATE DATABASE IF NOT EXISTS flower_member
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

也可以执行项目里的 `docs/init_db.sql`，内容就是上面这一句。库名必须是 `flower_member`。

### 4. 创建虚拟环境并安装依赖

```powershell
cd "新电脑上的项目路径"
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt
```

如果执行 `Activate.ps1` 被策略拦截：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

然后再激活一次。

主要依赖：`Django==5.2.7`、`django-jazzmin`、`PyMySQL`、`Pillow`、`python-dotenv`、`pytest-django`。Windows 用 PyMySQL 连接 MySQL，不需要编译 `mysqlclient`。

### 5. 配置 `.env`

```powershell
copy .env.example .env
```

用记事本打开 `.env`，至少改数据库密码：

```
SECRET_KEY=随便换一串本地密钥
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost

DB_NAME=flower_member
DB_USER=root
DB_PASSWORD=这里填新电脑的 MySQL root 密码
DB_HOST=127.0.0.1
DB_PORT=3306
```

密码填错会出现 `1045 Access denied`。密码为空时，多数 MySQL 8 默认也不让登录。

### 6. 迁移、导入演示数据、启动

```powershell
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

打开 http://127.0.0.1:8000/ 。首页与花市应能看到演示花品（种子数据约 13 款，含花束 / 绿植 / 礼盒）。

换电脑后如果商品没图：确认 `media/products/sku-*.jpg` 在，再执行一次 `python manage.py seed_demo`（不会冲掉已有演示订单）。

### 7. 新电脑验收

1. 首页、花市有商品图。
2. `demo_member` / `member123456` 能登录、加购、结算、模拟支付。
3. `admin` / `admin123456` 能进 `/admin/` 和 `/dashboard/`。
4. 可选：`python -m pytest`，应全部通过。

### 8. Mac / Linux 差异

```bash
python3.13 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# 编辑 .env 后：
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

MySQL 创建库的 SQL 相同。

### 9. 常见问题

| 现象 | 处理 |
| --- | --- |
| `No module named django` | 没有激活 `.venv`，或没执行 `pip install -r requirements.txt` |
| `1045 Access denied` | `.env` 的 `DB_PASSWORD` 与 MySQL 不一致 |
| `Unknown database 'flower_member'` | 还没执行建库 SQL |
| `Can't connect to MySQL` | MySQL 服务没开，或 `DB_HOST`/`DB_PORT` 不对 |
| 页面能开但商品没图 | 拷漏了 `media/products/`，或没跑 `seed_demo`。`config/urls.py` 在 `DEBUG=False` 时仍用 `serve` 挂本地 `/media/`，关调试模式不应导致花图 404 |
| 执行策略不允许运行 `Activate.ps1` | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `DisallowedHost` | `.env` 的 `ALLOWED_HOSTS` 加上当前访问的主机名 |

本项目是毕业设计演示，`DEBUG=True` + `runserver` 即可。不要用现在这套配置直接暴露到公网。

## 三、系统怎么分层

经典 Django MVT，业务规则放在各应用的 `services.py`，页面只负责收请求、调服务、渲染模板。

```
项目根目录
├── manage.py                 命令入口
├── .env / .env.example       数据库等本机配置
├── requirements.txt
├── config/                   全局配置与总路由
│   ├── settings.py           正式配置（读 .env，连 MySQL）
│   ├── settings_test.py      测试配置（SQLite）
│   ├── urls.py               总 URL
│   └── __init__.py           注册 PyMySQL
├── apps/
│   ├── accounts/             账号、角色、登录注册、后台权限
│   ├── members/              会员档案、积分、等级、储值
│   ├── products/             分类、商品、花市页面
│   ├── orders/               购物车、下单、模拟支付、退款
│   ├── marketing/            优惠券领取 / 核销 / 过期
│   ├── dashboard/            经营看板数据
│   └── core/                 首页、会员装饰器、演示数据
├── templates/                会员端 HTML
├── static/css/               前台 app.css、后台 admin.css
├── media/products/           商品图片
├── docs/                     论文/答辩用文档
└── tests/                    业务与页面测试
```

总路由在 `config/urls.py`：

| 前缀 | 模块 | 作用 |
| --- | --- | --- |
| `/` | `apps.core` | 首页 |
| `/accounts/` | `apps.accounts` | 登录、退出、注册 |
| `/shop/` | `apps.products` | 花市、详情、加购 |
| `/orders/` | `apps.orders` | 购物车、结算、订单、模拟支付 |
| `/member/` | `apps.members` | 会员中心、资料、积分/储值流水、领券 |
| `/dashboard/` | `apps.dashboard` | 经营看板 |
| `/admin/` | Django Admin + jazzmin | 管理员 / 店员后台 |

核心业务闭环：

**下单 → 预扣库存 → 核销优惠券 → 模拟支付 → 扣储值 / 记网关流水 → 发积分 → 升降级 → 流水入账 → 看板统计。**

取消待支付会回库存、退券。待支付超过 30 分钟未支付，进入首页、花市、订单页或看板时自动取消。已支付未发货须会员申请、店员或管理员审核后才退款。整单退款会回库存、回储值、扣回积分；已核销的券不退。

## 四、各模块核心代码

下面按“先看哪里、这个文件干什么”说明。写论文或答辩时，优先讲带 `services.py` 的四个文件。

### 1. 配置与入口

| 文件 | 作用 |
| --- | --- |
| `manage.py` | 设置 `DJANGO_SETTINGS_MODULE=config.settings`，执行 migrate / runserver 等 |
| `config/__init__.py` | `pymysql.install_as_MySQLdb()`，让 Django 在 Windows 上用 PyMySQL 连 MySQL |
| `config/settings.py` | `AUTH_USER_MODEL = accounts.User`、MySQL、模板、静态文件、媒体、Jazzmin 品牌色 |
| `config/settings_test.py` | 测试改用 SQLite，避免弄脏演示库 |
| `config/urls.py` | 挂载各应用 URL；始终用 `serve` 提供 `/media/` 访问商品图（不依赖 `DEBUG`） |

用户模型从第一天就自定义，不能中途再改 `AUTH_USER_MODEL`。

### 2. 账号与权限 · `apps/accounts`

| 文件 | 作用 |
| --- | --- |
| `models.py` | `User` 增加 `role`（admin / staff / member）和 `phone`。保存时按角色同步 `is_staff` / `is_superuser` |
| `forms.py` | 会员登录、注册表单；资料自改见 `apps/members/forms.py` |
| `views.py` | 登录成功：管理员/店员进后台，会员进会员中心；注册后自动建会员档案 |
| `rbac.py` | 建立「管理员」「店员」两组权限。店员可收银、管商品、发放优惠券、审核取消申请，不可管用户、不可创建券模板、不可对已发货单直接退款 |
| `signals.py` | 用户保存后调用 `apply_role`，把人放进对应权限组 |
| `admin.py` | 后台用户管理 |

会员不能进 `/admin/`。前台购物接口用 `member_required` 拦住非会员。

### 3. 会员、积分、等级、储值 · `apps/members`

核心文件：`apps/members/services.py`。

| 函数 | 作用 |
| --- | --- |
| `ensure_member_profile(user)` | 会员账号自动建档案和储值账户 |
| `refresh_level(member)` | 按累计积分套档：普通 0 / 银卡 1000 / 金卡 5000 / 钻石 10000 |
| `apply_points(...)` | 加减积分、写 `PointsRecord`、再升降级。积分不为负 |
| `apply_store(...)` | 加减储值、写 `StoreRecord`。余额不足抛错 |
| `recharge(...)` | 管理员后台调账入口 |
| `create_store_recharge` / `pay_store_recharge` | 会员自助充值；失败不关单，成功才入账 |

`models.py` 对应表：`MemberLevel`、`Member`、`PointsRecord`、`StoreAccount`、`StoreRecord`、`StoreRecharge`。

等级折扣和积分倍率：

| 等级 | 累计积分 | 折扣 | 积分倍率 |
| --- | --- | --- | --- |
| 普通 | 0 | 100% | 1.0 |
| 银卡 | 1000 | 98% | 1.1 |
| 金卡 | 5000 | 95% | 1.2 |
| 钻石 | 10000 | 92% | 1.5 |

支付成功后：积分 = ⌊实付金额 × 当前等级倍率⌋，1 元对应 1 积分再乘倍率。

前台页面：`views.py` 的会员中心、资料自改、积分/储值流水、领券；模板在 `templates/members/`。

### 4. 商品 · `apps/products`

| 文件 | 作用 |
| --- | --- |
| `models.py` | `Category`、`Product`（价格、库存、上下架、`ImageField` 图片） |
| `views.py` | 花市列表、分类筛选、关键词搜索、详情、加入购物车 |
| `admin.py` | 后台改库存/上架，列表显示缩略图 |

图片存在 `media/products/`，字段是 `Product.image`。演示数据在 `seed_demo` 里按 SKU 挂图。

### 5. 订单与模拟支付 · `apps/orders`（最核心）

核心文件：`apps/orders/services.py`。页面在 `views.py`，只调用这些函数。

| 函数 | 作用 |
| --- | --- |
| `calculate_amounts` | 应付 = 商品合计 − 等级折扣 − 优惠券，结果不为负 |
| `add_to_cart` / `set_cart_quantity` | 购物车，同一商品合并数量；数量不能超过当前库存 |
| `create_order_from_cart` | 锁购物车行后生成待支付订单、快照明细、**预扣库存**、核销优惠券、清空购物车 |
| `reserve_stock` / `restore_stock` | 下单扣库存；取消或退款回补。用 `select_for_update` 防超卖 |
| `pay_order(success=True/False)` | 模拟支付。失败只记失败流水、订单仍待支付；成功则扣储值、记网关流水、发积分、改已支付 |
| `cancel_order` | 仅待支付：回库存、退券 |
| `cancel_unfulfilled_order` | 会员取消：待支付走取消；已支付未发货只提交待退款审核 |
| `request_cancel` / `approve_cancel` / `reject_cancel` / `withdraw_cancel` | 申请、同意退款、驳回、会员撤回。审核中不能发货或自提 |
| `expire_pending_orders` | 待支付超过 30 分钟：自动取消。访问首页、花市、订单、结算、会员中心或看板时扫描，也可用管理命令 |
| `ship_order` / `receive_order` / `pickup_order` | 发货、会员签收、店员自提核销。`completed` = 已签收 |
| `complete_order` | 内部转发：配送中→签收，自提已支付→核销 |
| `refund_order` | 已支付/待审核/配送中/已签收：回库存、回储值、扣积分。店员无直接退款，只能审核申请 |

订单状态：

```
待支付 → 已支付 → 配送中 → 已签收
待支付 → 已支付 → 已签收（自提）
待支付 → 已取消
已支付 → 待退款审核 → 已退款
待退款审核 → 已支付（驳回 / 撤回）
已支付 / 待退款审核 / 配送中 / 已签收 → 已退款
```

金额拆分写在 `Order` 上：`goods_amount`、`level_discount_amount`、`coupon_amount`、`payable_amount`、`store_paid_amount`、`gateway_paid_amount`。  
`OrderItem` 保存下单时的名称、SKU、单价快照，商品以后改价不影响历史订单。

### 6. 优惠券 · `apps/marketing`

核心文件：`apps/marketing/services.py`。

| 函数 | 作用 |
| --- | --- |
| `receive_coupon` / `issue_coupon` | 会员领取或后台发放，检查有效期、总量、每人限领 |
| `compute_discount` | 满减或折扣；门槛看商品合计；抵扣发生在等级折扣之后 |
| `redeem_on_order` | 下单核销。可指定券，或自动选最优可用券。一单一张 |
| `release_order_coupon` | 取消待支付时把券退回「已领取」 |
| `expire_due_issues` | 把过期未用的券标成已过期 |

命令：`python manage.py expire_coupons`。

支付成功后再退款，**不退券**。

### 7. 经营看板 · `apps/dashboard`

| 文件 | 作用 |
| --- | --- |
| `services.py` 的 `dashboard_payload()` | 汇总近 14 天：销售额、订单数、会员增长、等级分布、畅销商品、积分/储值/券 |
| `services.py` 的 `staff_desk()` | 待支付订单、库存 ≤ 8 的在售花品 |
| `views.py` | 仅 `is_staff` 可看，否则 403 |
| `templates/dashboard/index.html` | 店务待办 + 本地 ECharts 6.0（`static/vendor/echarts.min.js`）六张图 |

只统计已支付、待退款审核、配送中、已签收订单的实收（储值 + 模拟网关）。`PAID_STATUSES` 含 `cancel_requested` 与 `shipped`。审核通过前仍算实收。

### 8. 公共与演示数据 · `apps/core`

| 文件 | 作用 |
| --- | --- |
| `decorators.py` 的 `member_required` | 必须登录且角色为会员，并把 `request.member` 准备好 |
| `context_processors.py` | 全站导航高亮、购物车数量角标 |
| `views.py` | 首页在售花品 |
| `management/commands/seed_demo.py` | 演示账号、13 个商品及图片、会员积分储值、优惠券、近两周订单 |

### 9. 页面与样式

- 会员端模板：`templates/`（`base.html`、首页、花市、购物车、结算、订单、会员中心、登录注册）
- 前台样式：`static/css/tokens.css` + `app.css`，品牌色 `#355E4B`
- 后台皮肤：Jazzmin + `static/css/admin.css`

后台改商品、库存、发券、发货 / 自提核销都在 `/admin/`。储值由会员自助充值或管理员调账；整单直接退款仅管理员。不另写一套管理前端。

### 10. 测试

- `tests/test_business.py`：积分、储值、下单、支付、退款、优惠券、待支付超时
- `tests/test_views.py`：公开页、会员页、资料/流水、花市搜索、店员看板与待办

测试走 `config/settings_test.py` 的 SQLite。

## 五、核心调用链（答辩可按此讲）

会员在花市点「加入购物车」：

1. `apps/products/views.py` 的 `product_add_cart`
2. `apps/orders/services.py` 的 `add_to_cart`

结算提交：

1. `apps/orders/views.py` 的 `checkout`
2. `create_order_from_cart`：写订单和明细 → `reserve_stock` → `redeem_on_order` → 清空购物车
3. 跳到订单详情

模拟支付成功：

1. `order_pay` → `pay_order(success=True)`
2. 有储值则 `apply_store` 扣余额
3. 剩余记一条模拟网关成功流水
4. `apply_points` 发积分，`refresh_level` 升降级
5. 订单变为已支付，看板下次打开即可看到

管理员在后台点整单退款：

1. `refund_order`
2. 回库存、回储值、扣积分，状态变为已退款
