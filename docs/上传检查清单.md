# 上传 GitHub 检查清单

代码已经在本地（当前分支 `main`）。公开前按下面做一遍，避免把密码或未完成口径传上去。

## 1. 先改两处署名

1. `LICENSE` 第 3 行：把「花间集项目作者」改成你的姓名。
2. 论文封面、致谢里的姓名与仓库作者页保持一致即可，不必写学号进 LICENSE。

## 2. 确认不会被提交的文件

这些必须留在本机，`.gitignore` 已忽略：

- `.env`（含 MySQL 密码）
- `.venv/`、`__pycache__/`、`.pytest_cache/`
- `CURSOR_RULES.md.txt`（与 `CURSOR_RULES.md` 重复的草稿）

推送前执行：

```powershell
git status
git check-ignore -v .env .venv
```

`.env` 应显示被忽略。若 `git status` 里出现 `.env`，立刻停下来，不要 `git add .`。

## 3. 建议提交的文档

| 文件 | 是否提交 |
| --- | --- |
| `README.md` `LICENSE` `SECURITY.md` `CONTRIBUTING.md` | 要 |
| `docs/` 下概述、规则、部署、演示、答辩要点、截图 | 要 |
| `docs/screenshots/*.png` `media/products/*.jpg` | 要（答辩和克隆仓库都靠它们） |
| `CURSOR_RULES.md` | 可选。这是给 AI 的开发约束，不是给评阅人看的；不放也不影响运行 |
| 带「审计报告」的过程稿 | 可选。已加「过时」说明；若怕评阅人读到旧口径，可先不纳入本次提交 |

## 4. 仓库怎么建

1. 在 GitHub 新建仓库。答辩前若担心题目被看或学校查重，选 **Private**。
2. 不要勾选 GitHub 自动生成的 README / License（本仓库已经有了，勾选会先产生无关的首次提交）。
3. 本地若尚未关联远程：

```powershell
git remote -v
```

若还没有 `origin`：

```powershell
git remote add origin https://github.com/你的用户名/你的仓库名.git
git add README.md LICENSE SECURITY.md CONTRIBUTING.md docs .gitignore
git add -u
git status
```

确认没有 `.env` 后，再按你的习惯提交并 `git push -u origin main`。

本清单不代替你发出「帮我提交 / 推送」的明确指令；未要求时不会替你 `git commit` 或 `git push`。
