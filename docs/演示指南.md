# 演示指南

给导师、评阅人或克隆仓库的人用。按下面顺序操作，大约 10–15 分钟可以走完主闭环。  
默认已执行 `python manage.py migrate` 与 `python manage.py seed_demo`，服务在 http://127.0.0.1:8000/ 。

建议浏览器使用两个窗口（或无痕窗口）：一个登录会员，一个登录店员 / 管理员，避免来回退出。

---

## 一、会员：选花到支付

账号：`demo_member` / `member123456`

1. 打开首页，确认标语「以花为集，以客为心」和花品图。
2. 进入 **花市**，用分类或关键词（花名 / 花语 / SKU，如 `玫瑰` 或 `SKU-R12`）筛选。
3. 打开商品详情，数量不超过库存，加入购物车。种子数据已给该账号预置购物车，可直接进购物车核对。
4. 结算页勾选：
   - 履约：先选 **送花上门**，确认收花人 / 电话 / 地址快照；
   - 储值抵扣开关；
   - 一张可用优惠券（一单一张，系统也可自动选最优券）。
5. 提交订单，进入待支付页。此时库存应已预扣，券应变为已核销占用。
6. 先点一次 **模拟支付失败**：订单仍待支付，只多一条失败流水。
7. 再点 **模拟支付成功**：储值优先扣，剩余走模拟网关；积分到账，等级按净值套档。

可选补充：

- **会员中心**：看当前等级、积分、储值与权益说明。
- **积分与储值**：核对刚才那一单的流水。
- **自助充值**：选档位（50–2000 元），模拟成功后余额增加，**不赠积分**。失败不关单。
- **我的优惠券**：领取一张未领完的券，下一单再用。

待支付超过 30 分钟会自动取消（回库存、退券）。演示超时可用管理命令，不必真等半小时：

```powershell
python manage.py expire_pending_orders
```

## 二、店员：履约与审核

账号：`staff` / `staff123456`  
入口：http://127.0.0.1:8000/admin/ 与 http://127.0.0.1:8000/dashboard/

1. 登录后台，确认侧栏**没有**用户管理，会员多为只读，**没有**「储值充值金额」。
2. 打开刚才那张已支付的配送单，执行 **发货**。订单变为配送中。审核中的取消申请不能发货。
3. 切回会员窗口，订单详情点 **确认签收**。`completed` 表示已签收，不是「系统自动结案」。
4. 另下一单，结算选 **到店自提**。支付成功后，会员看不到「我已自提」；回到店员后台做 **自提核销**。
5. 再下一单并支付（配送、未发货），会员点 **申请取消**。店员在订单上 **同意**（整单退款：回库存、回储值、扣积分，券不退）或 **驳回**。
6. 打开看板：顶部待办应出现待支付、待履约、待审核取消、库存 ≤ 8 的花品；下方六张图有近 14 天数据。

店员**不能**对已发货 / 已签收单直接点退款。要演示直接退款，必须换管理员。

---

## 三、管理员：调账、退款、规则

账号：`admin` / `admin123456`

1. 后台 → **会员** → 打开一名会员，填写「储值充值金额」并保存，流水类型为后台调账。
2. 打开一张已签收或配送中的订单，执行 **整单退款**。库存回补，储值回补，该单积分扣回，等级可能下降。
3. **优惠券**：管理员可创建模板；店员只能发放已有模板。
4. **用户**：可改角色。保存后会同步 `is_staff` / 权限组。不要把演示会员改成店员后还用前台购物。
5. 看板与店员同一地址，管理员多看退款与全店数据即可。

等级字段不要手改。钻石必须靠累计积分到 10000。

## 四、建议的答辩 8 分钟切法

| 分钟 | 窗口 | 动作 | 要让老师看见 |
| --- | --- | --- | --- |
| 0–1 | 会员 | 首页 + 花市搜索 | 有图、有分类、有品牌 |
| 1–3 | 会员 | 结算（配送 + 储值 + 券）→ 失败再成功 | 金额拆分、库存预扣 |
| 3–4 | 会员 | 会员中心 + 流水 | 积分倍率、储值余额 |
| 4–6 | 店员 | 发货 / 签收或自提；看板待办 | 角色差异、履约不是物流公司 |
| 6–7 | 会员 + 店员 | 申请取消 → 审核 | 已支付不能自己退 |
| 7–8 | 管理员 | 看板六张图 + 一句退款口径 | 实收来自订单，不是另一套统计 |

若现场数据库被玩乱：

```powershell
python manage.py seed_demo --force
```

只会清带来源标记「演示数据」的订单并重建，不会删你新注册的真实测试号（除非你也用了同一备注）。商品图仍在 `media/products/`。

## 五、演示时不要做的事

- 不要在 Admin 里直接改订单 `status` 下拉框来「变成已支付」（字段应只读；即使以后被改开，也会绕过扣款和积分）。
- 不要用店员账号演示充值或已发货退款，会被认为权限做错。
- 不要说「已经对接微信支付」「已经接了顺丰」。
- 不要在公网或教室大屏长期停留登录态后把电脑留给别人，演示密码是公开的。
