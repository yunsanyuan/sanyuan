## 1. 开场 30 秒

「花间集是一个花店会员管理演示系统。会员在前台选花、用等级折扣和优惠券下单，支付是模拟网关，可以扣储值。店员在后台备花、发货或核销自提，管理员看经营看板。我做的不是电商平台，而是把库存、储值、积分、优惠券算在同一笔订单上的店内闭环。」

## 2. 能答

### 功能闭环

- 下单生成待支付时：**预扣库存**，并核销一张券（指定或自动选最优）。
- 模拟支付失败：只记失败流水，订单仍待支付，不扣储值、不发积分。
- 模拟支付成功：储值优先、剩余走网关；积分 = ⌊实付 × 当前等级倍率⌋；按累计积分净值套档。
- 取消待支付或 30 分钟超时：回库存、退券。扫描发生在进入首页、花市、订单、结算、会员中心、看板时，也可用 `expire_pending_orders`。没有 Celery。
- 支付成功后再退款：回库存、回储值、扣该单积分（可能降级），**不退券**。
- 后台订单 **status 只读**，支付 / 发货 / 退款走 Admin 动作，进入服务函数。

### 履约（店内语义）

- 结算可选 **送花上门** 或 **到店自提**，地址在下单时快照，已支付后不能改。
- 配送：已支付 → 配送中（店员发货）→ 已签收（会员点确认签收）。
- 自提：已支付 → 已签收（仅店员核销）。会员不能自己点「我已自提」。
- `completed` 的含义是 **已签收**，不是「没有后续的完成」。
- 这不是快递系统：没有运单号、轨迹、货到付款、上门取件。

### 储值

- 两条入金：会员中心自助充值（模拟网关，1–2000 元，档位固定）；管理员后台调账。
- 自助充值单独一张 `StoreRecharge`，成功才入账，失败不关单，不赠积分。待入账 30 分钟超时。每人同时一张待入账。
- **店员不能充值**，也没有后台调账框。

### 取消与权限

- 已支付未发货（或自提未核销）：会员只能 **申请取消**，库存继续占用，防止占货后立刻退款。
- 店员或管理员同意后整单退款；驳回或会员撤回后继续履约。审核中不能发货 / 核销。
- 已发货后会员不能申请；管理员仍可直接退款（不模拟退货物流）。
- 店员：可发券、可审核取消；不可管用户、不可建券模板、不可对已发货单直接退款。
- 会员不能登录 `/admin/`。

### 数据与看板

- 金额：应付 = 商品合计 − 等级折扣 − 优惠券；实付 = 储值 + 网关。
- 流水带变动后余额。
- 看板只统计已支付、待退款审核、配送中、已签收的实收。待审核通过前仍算实收。充值不是花市销售额。
- 下单 / 支付 / 取消 / 退款 / 积分 / 储值走 `transaction.atomic`，库存与账户使用 `select_for_update`。

### 工程

- 自定义用户从第一天就设定 `AUTH_USER_MODEL = accounts.User`。
- 测试 `python -m pytest` 使用 SQLite，不改 MySQL 演示库。
- ECharts 文件在 `static/vendor/echarts.min.js`，断网可看。

## 3. 必须承认（老师追问时主动说）

| 问题 | 建议答法 |
| --- | --- |
| 为什么没有微信支付？ | 题目范围和导师清单都不接真实网关。我用成功 / 失败两按钮模拟入账，保证后面的库存和积分逻辑可演示、可测试。 |
| 为什么没有物流公司？ | 花店场景做成店内履约：发货、签收、自提核销。再做运单会变成物流系统，超出毕业设计范围。 |
| 高并发超卖解决了吗？ | 单库行锁 `select_for_update`，测试覆盖单线程库存不足。没有分布式锁，也没有压测报告，不能说「已经解决高并发」。 |
| 优惠券会不会并发超领？ | 服务层先锁券模板再计数；表上没有 `(coupon, member)` 唯一约束。演示双击较难复现，论文里应写明这是已知限制。 |
| 过期订单谁来扫？ | 不用定时任务。访问关键页面时扫描，另提供管理命令。答辩机器一直开着首页也能触发。 |
| 累计积分退款为什么会变少？ | 文档定义的是**净值**：退货就把该单积分扣回，等级跟着降。否则钻石可以靠退款刷出来。 |
| 店员为什么不能充值？ | 资金入口收口：会员自己充，或管理员调账，避免店员口头收款却在系统里加余额。 |
| 能直接上线吗？ | 不能。`DEBUG` 默认打开，密钥在 `.env`，演示密码公开，没有生产部署方案。 |

## 4. 禁止说

- 「全业务流程都闭环」（缺真实支付、第三方物流、多门店售后）。
- 「已经对接支付 / 已经上线 / 已经解决高并发」。
- 「店员也可以给会员充值」。
- 「退款后优惠券会退回」（仅取消待支付退券）。
- 「完成订单没有配送」（旧文档的话，现在有发货和签收）。
- 「储值只能管理员加」（旧文档的话，现在有自助充值）。

## 6. 现场应急

- 商品没图：确认 `media/products/sku-*.jpg` 在，再跑一次 `seed_demo`。
- 看板是平的：`python manage.py seed_demo --force`。
- 待支付单太多：执行 `expire_pending_orders` 或用会员取消。
- 权限演示乱了：不要改 `demo_member` 的角色；用种子账号重新登录。
- 老师要看测试：`python -m pytest`，说明这是 SQLite，不会冲掉刚演示的 MySQL 数据。
